# Security rules for AI coding assistants

Generated by vibe-it-securely. Follow these in all code you write or modify.

## Always
- Never hardcode secrets, tokens, passwords or API keys. Read them from environment variables and add new ones to `.env.example` with empty values.
- Validate and sanitize all external input (request bodies, query params, files, env vars).
- Use parameterized queries or an ORM. Never build SQL by string concatenation.
- Add authentication AND authorization checks to every endpoint that touches user data.
- Keep CORS restrictive: list allowed origins explicitly, never `*` with credentials.
- Do not log secrets, tokens or personal data.
- Prefer well-maintained libraries; do not add a dependency for something trivial.
- Run containers as a non-root user.

## Never
- Never disable TLS verification or security linters to make an error go away.
- Never commit `.env`, private keys or credentials.
- Never use `--no-verify` to skip the pre-commit hooks.

## JavaScript / TypeScript
- Never use `eval`, `new Function`, or `child_process.exec` with user input.
- Validate request data with a schema library (e.g. zod) at the API boundary.
- Never render user input with `dangerouslySetInnerHTML` or `innerHTML` unsanitized.

If a task seems to require breaking a rule above, stop and ask the user first.
